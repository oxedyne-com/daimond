あなたのコンピューター

Daimond は、カーネルが強制する隔離領域の中で、あなたのコンピューター上のプログラム（ビルド、テストスイート、リンター、スクリプト）を実行できます。無料で、ターミナルでの二つのコマンドで済み、Linux 専用です。どちらかのコマンドを打つ前に、まず警告を読んでください。

snap や flatpak のブラウザにはこれができず、できるようにもできません。 インストーラーはそれを検出すると、書き込む代わりに拒みます。ですからこれが最初に出会うことになるもので、Ubuntu の既定の Chromium は snap です。 なぜか、そして代わりに何を入れるべきか.

それが与えてくれるもの

hand をインストールすれば、daimon は、あなたが付与したフォルダーに対してビルド、テストスイート、リンター、スクリプトを実行し、結果を読めます。その機器のほかのものには届きません。

それが使うツールは、 ツール パネルに名前が挙がっており、そのうち四つは名前を知っておく価値があります。

  • run は、引数の一覧として与えられた一つのコマンドを実行し、終了コード、出力の末尾、かかった時間で答えます。
  • verify は、あなたのプロジェクト自身の検査を実行します。Daimond は argv を .daimond/verify.jsonから読むか、 Cargo.toml, package.json, pyproject.toml または go.modから推測します。終了コードが判定です。
  • runs は、まだ動いているものを一覧にし、止め方を示します。コマンドはやり取りより長生きすることがあります。バックグラウンドで始まった何かが、止められるまでポートを持ち続けるからです。コンピューターのほかの何もそれには届きません。隔離領域はシグナルを自分自身に限るからです。
  • serve は、フォルダーに対して読み取り専用のファイルサーバーを起動し、ビルドされたページを ウェブ パネルで見られるようにします。やり取りが終わっても動き続けるので、ID で止めてください。

拒否は、パスと原因と直し方を名指しするので、調べるべきコードはありません。やり取りは、そのあとどのやり取りとも同じように終わります。 回答済み, 停止 または 手順の上限に到達のいずれかとして。ですから拒否されたコマンドが、うまくいったかのように読めることはありません。

始める前に

これがうまくいくかどうかは、三つのことで決まります。確かめるのに一分もかかりませんが、あとから気づくのには一時間かかります。ブラウザが報告するエラーは、そのどれも名指ししないからです。

1. インストール元が .deb

のブラウザであること。snap や flatpak のブラウザは、起動するプログラムを閉じ込めます。その閉じ込めは、Daimond の hand にも及びます。 home というインターフェース——snap が受け取るもの——は、ホームディレクトリの直下にある隠しディレクトリを付与しません。hand はジャーナルを ~/.local/share/daimond/hand/journal/その中に置きます——それらの一つの裏に。hand は、理由を記録していたはずのファイルを開けないので、何も言わずに終了し、Chrome はただ Native host has exitedとだけ報告します。この一文では、何もできません。そしてその閉じ込めこそが snap の目的です。ジャーナルを移しても助けにはなりません。ブラウザはそのプログラムに、それ自身の環境を渡すからです。

これを自分で解き明かす必要はありません。インストーラーは、使えるプロファイルには書き込み、使えないものは名指しします。見つけたブラウザがすべて閉じ込められていれば止まるので、うまくいったように見えるだけのインストールが残ることはありません。 --check は、隣に使えるブラウザがあっても、閉じ込められたブラウザに印を付けます。実際に使っているブラウザが決め手だからです。

始める前に、何を持っているか確かめるには：

snap list 2>/dev/null | grep -Ei 'chrom|brave|vivaldi|edge'
flatpak list 2>/dev/null | grep -Ei 'chrom|brave|vivaldi|edge'

どちらのコマンドが名指ししたものも閉じ込められています。使えるのは、Chrome、Brave、Vivaldi、Edge を .debとしてインストールしたもの、あるいは Chromium の .deb を、Ubuntu のアーカイブ以外の場所から入れたものです。

apt install chromium-browser は、snap を与えます。 Ubuntu の chromium-browser パッケージは、20.04 以来、snap をインストールするだけの空の中身になっています。ですから Software アプリを使わずにブラウザを手に入れるふつうの方法でも、同じ場所に行き着きます。上の四つの .debのどれかを、代わりにインストールしてください。

2. インストールする前に、そのブラウザを一度実行する

インストーラーは、ブラウザのプロファイルディレクトリに小さなファイルを一つ書き込みますが、そのディレクトリはブラウザが最初に起動したときに作られます。ブラウザをインストールして一度も開かなければ、 install.sh は、正しくも何も見つからないと報告します。まだそこに何もないからです。

3. Linux で、カーネルに Landlock があること

隔離領域は、ファイルを柵で囲む Landlock と、システムコールをフィルターする seccomp から組み立てられています。どちらも Linux カーネルの機能です。Landlock は Linux 5.13 で登場しました。そして 型破りなシステム が、古い、あるいは珍しい機器に何が起きるかを記しています。hand は macOS と Windows でもビルドされ動きますが、何も柵で囲めないと報告し、Daimond はそのため柵のないコマンドを実行する代わりに、すべてのコマンドを拒みます。拒否は、何が欠けているかを名指しします。どちらのプラットフォームの柵も組み立てられていません。

別のブラウザをインストールしますか？ アカウントは一緒には来ません。 あなたのアカウントは、それを作ったブラウザに置かれた署名鍵です。パスフレーズはその鍵を作り直すのではなく、そこにすでに保存されている写しを復号するだけです。ですから、まっさらなブラウザで同じパスフレーズを使っても、始まるのは 別の アカウントで、クレジットもそれ自身のもの、Pro もありません。鍵は渡っていく必要があるので、古いブラウザを退役させる前に、そこで次のどれかを行ってください。 ほかの端末をリンクしてから、新しいブラウザにコードを入力する。パスキーを追加する。あるいは バックアップを書き出す。チャット、diamond、作業領域のファイルを、まだパスフレーズのもとで包まれたままの鍵と一緒に書き出し、まだ自分のアカウントを持たないブラウザのために使います。詳しくは 複数の端末 と 安全性と対処.
「この端末」の作業領域とは別のものです。 この端末 のチップは、 作業領域 パネルにあり、ディスク上の本物のフォルダーへの読み書きアクセスを Daimond に与えます。「端末でのコマンド実行」がそれに許すのは プログラムを実行することです。これらは別々に与えられる、別々の許可です。コマンド実行の側は作業領域を必要とします。コマンドは本物のフォルダーに対して走るので、作業領域はフォルダーでなければならず、しかも同じフォルダーでなければなりません。

インストールする

インストールには、Daimond リポジトリのトップから、ターミナルでの二つのコマンドと、そのあとブラウザでの二つのことが要ります。合わせて、ブラウザのプロファイルごとの小さな JSON ファイル一つと、あなたがビルドしたバイナリになります。インストールは、ポートで待ち受けるものも、動いているデーモンも、盗まれる秘密も何も残しません。

  1. hand をビルドする

    cargo build --release --manifest-path hand/Cargo.toml

    使うのは --manifest-path であって -pではありません。hand はそれ自身の cargo ワークスペースだからです。ですから -p は、そんなパッケージはないと報告し、何もビルドしません。

  2. フォルダーを付与し、hand を登録する

    hand/install/install.sh --workspace ~/work

    自分のフォルダーを、 ~/workの場所に置いてください。そのフォルダーが、どのコマンドでも読み書きできるものすべての境界になります。仕事用に一つ選んでください。スクリプトは、あなたのホームディレクトリと / を、はなから拒みます。どちらを付与しても、すべてを付与することになるからです。フォルダーはあらかじめ存在していなければなりません。

    その一回の実行は三つのことを行い、それぞれ、やらなければあとで出会うはずの失敗を防ぎます。

    • あなたのフォルダーを root.txtに書き込みます。場所は ~/.local/share/daimond/hand/journal/root.txtです。hand は、そのフォルダーを教えられるまでページを提供しません。決して推測しません。推測したフォルダーは、コマンドが何に触れてよいかについての推測になるからです。あとで変えるには、別のフォルダーで同じコマンドを実行してください。
    • そのジャーナルディレクトリをモード 700 で作ります。 そこには、すべての diamond が実行したすべてのコマンドの記録が入るので、hand はほかのユーザーが読める場所には書き込みを拒みます。ふつうの既定の権限で作られたディレクトリは 755 であり、それでは hand は起動しません。
    • 登録を書き込みます 。使えるすべてのブラウザプロファイルに書き込み、どれかを表示します。このファイルこそが、ブラウザに hand を起動させる唯一のものです。JSON でしかないので、スクリプトは何もビルドせず、何もダウンロードせず、何も起動せず、root も必要としません。
    DAIMOND_HAND_ROOT は罠です。 この環境変数は、 root.txt と同じ仕事をし、しかも優先されますが、うまくいきません。あなたのブラウザは、hand を それ自身の 環境で起動し、あなたの環境はそこに含まれないからです。ファイルを使ってください。

  3. 拡張機能を読み込む

    前の手順がパスを表示しています。 chrome://extensionsを開き、 デベロッパーモードをオンにして、 パッケージ化されていない拡張機能を読み込むを選び、 ext/ ディレクトリを選択します。

    この拡張機能は固定された公開鍵を持つので、その ID はどの機器でも同じです。だからこそ、少し前に書き込まれた登録が、すでにそれを名指しできます。そのマニフェストは、単一のオリジン https://daimond.oxedyne.comだけを、話しかけることを許されたページとして名指しします。ですからあなたのブラウザのほかのどのページも、それにはまったく届きません。

  4. ブラウザを再起動する

    ブラウザがそれらのプロファイルディレクトリを読むのは、起動するときだけです。動いているあいだに現れたファイルは、そのときまで見えません。再起動を忘れることが、正しいインストールが壊れているように見える、いちばんよくある理由です。

そして確かめる

hand/install/install.sh --check

この確認は何も変えず、真であるべきことごとに一行を表示します。使えるブラウザ、登録、バイナリ、ジャーナルディレクトリとそのモード、 root.txt、付与されたフォルダーの外にあるジャーナル、そして拡張機能です。失敗した行には、その下の行に直し方が添えられます。上から取り組んでください。あとの行が失敗するのは、たいてい前の行が失敗したせいでしかないからです。

最後の二つの手順はあなたのもの

上の手順のどれも、あなたに代わって決めたものはありません。残る二つが、決断そのものです。

同じフォルダーを Daimond で開く。 作業領域パネルで、 この端末 のチップを使い、付与したフォルダーを開いてください。同じものでなければなりません。hand はトークンを <folder>/.daimond/workspace.id に書き込み、自分を紹介するときにそれを名指しします。ページは、すでに持っているハンドルを通してそのファイルを読み、両者を見比べます。作業領域がブラウザ自身の保存領域である場合、あるいは root.txtとは違うフォルダーである場合、コマンドはどちらが違うかを一行で伝えられて拒まれます。トークンがあるのは .daimond の内側です。隔離領域は常にそのディレクトリを拒むので、コマンドはトークンを読めず、自分がいないフォルダーについて答えることもできません。

最初のコマンドを許可する。 Daimond が何かを実行しようとする最初のとき、 Daimond Hands というウィンドウが開いて尋ねます。「このコンピューターでプログラムを実行してよい」を対象にするブラウザの許可はありません。ですからそのウィンドウ こそが 承認そのもので、拡張機能自身があなたの答えを記録します。だからこそ取り消せるのでもあります。ブラウザには取り去るものが何もないからです。あなたが許可するまで、何も走りません。

ウィンドウは、フォルダーと尋ねてきたページを名指しし、この機器でコマンドがどこまで届くかを一行で伝えます。 これが対象にすること、しないこと が、残り——隔離領域が止めるもの、止めないもの、そして許可を取り下げる方法——を開きます。

うまくいかないとき

まずは install.sh --check をもう一度。ここにあるすべての確認を順に歩き、最初に間違っているところで止まります。これが自動化している三つの手順は、それ自体でも役に立ち、 --check が通っているのに Daimond がまだ hand がないと言うとき、頼るべきものです。

hand を自分で実行する

hand/target/release/daimond-hand < /dev/null

これは、あなたのブラウザがするのとまったく同じように hand を起動しますが、反対側にブラウザはありません。ですから、ブラウザに言うはずだったことを、あなたに言います。答えは三つあります。

  • daimond-hand: the page closed the pipe. hand は設定済みで準備できています。何か問題があるとすればブラウザの側で、まず再起動を試してください。
  • 「この hand は、どのフォルダーで働いてよいか教えられていません」 は、 root.txt が欠けている、という意味です。 install.sh --workspace をもう一度実行してください。
  • 「…は、所有者以外のユーザーにも読める」 は、ジャーナルディレクトリが 700 になっていない、という意味です。hand は、ほかのアカウントが読める場所に、あなたのコマンドの記録を書きません。 chmod 700 してください。

それ以外は、パスと原因と直し方を名指しする、まるごとの一文です。hand には、誰かが調べられるようなコードを表示する場所がないからです。

hand/target/release/daimond-hand --report

これは、隔離領域が この カーネルで強制できることと、より詳しく、できないことを表示します。二つ目の一覧はよく読んでください。Linux 7.1 より前のカーネルでは、そこに 隔離領域から出る道 が含まれます。それは Landlock が開けたままにしているもので、hand は unix ソケットを拒むことで自分でそれを閉じます。これはまた、 root.txtからフォルダーも名指しするので、古くなったものは最初のコマンドではなくここに現れます。

ジャーナルを読む

tail -n 5 ~/.local/share/daimond/hand/journal/hand-*.jsonl

ジャーナルは、起きたことの順に、一行に一つの JSON オブジェクトを保ちます。ハンドシェイク、すべてのコマンド、そして理由を添えたすべての拒否です。hand がとにかく起動していれば、ここに何か書かれています。失敗した試みのあとに空のディレクトリしかなければ、hand が十分に遠くまでたどり着けなかった、という意味です。Ubuntu では、それはほとんど常に、このページの冒頭にある閉じ込められたブラウザを意味します。

拡張機能に尋ねる

ブラウザで、Daimond のタブを開き、デベロッパーコンソールを開いて、次を実行してください。

await DaimondHand.status()

拡張機能は、hand がペアリングされているか、どのフォルダーを付与されたと言っているか、何を強制できるか、そして答えがノーの場合には reason を、まるごとの一文として書いた JSON で答えます。Daimond はモデルにもその同じ一文を見せるので、この JSON は daimon が何を伝えられたかを説明しています。

実際のところ何なのか

コマンドとは、あなたが所有する、あなた自身のカーネルで、あなた自身のファイルに対して走る、ふつうのプロセスです。ただしケーパビリティは先に取り除かれています。仮想マシンも、コンテナも、エミュレーションもありません。ですから何もシミュレートされず、何もコピーして持ち込まれません。四つの部分が、それぞれ一つの仕事をします。

  • ページが尋ねる。 Daimond は、このやり取りが何に触れてよいかを算出し、規則をまるごと要求と一緒に送ります。シェルの行を送ることは決してありません。 argv——引数の一覧——は配列であり、注入する先が何もないからです。
  • 拡張機能が中継する。 Daimond Hands は、ページがコマンドを渡せる唯一のもので、話しかけられるオリジンは一つだけです。
  • 小さなローカルのプログラムがそれを実行する。 hand は、送られてきた規則から隔離領域を組み立て、自分自身にそれを適用し、そのあと なります そのコマンドそのものに。子を見張る監督はいません。コマンドが始まった時点で、hand には何も残っていないからです。
  • あなたのブラウザが hand を起動する。 だからこそ、ポートもパスワードもありません。ポートで動くサービスは、訪れるどのページからも届いてしまいます。
無料で、Pro の一部でもありません。 コマンドにまつわる何も、Daimond のゲートウェイに触れません。要求はページから拡張機能へ、あなた自身のディスクにあるプログラムへ、そしてまた戻ります。ですから計測されるものは何もありません。コマンドの費用は、それについて考えるモデルの費用だけで、ほかのどのやり取りとも同じです。

Daimond はツールを実装していません

組み込みの lsはなく、組み込みの grepもありません。同梱のツール箱もシェルもありません。 ls こそが /usr/bin/lsは、あなたの機器にすでにある、インストールしたバージョンのそれです。

システムディレクトリの下にあるプログラムはすべて届きます。隔離領域が、それらを付与に加えるからです—— 読み取り専用: /usr, /bin, /sbin, /lib, /lib32, /lib64, /libx32, /etc, /optで。そして無害なデバイス /dev/null, /dev/zero, /dev/full, /dev/random と /dev/urandom。これらがなければ何も起動しません。 catさえも。ローダーは共有オブジェクトを読まなければならず、プロセスは標準ストリームのために何かを開かなければならないからです。

そのままの名前は、 PATHで探されます。それは /usr/local/bin:/usr/bin:/bin です。付与されたツールチェーンがそこに何かを加えていないかぎりは。そこで見つかったものは絶対パスに解決され、ほかの何とも同じように隔離領域と照合されます。見つかることは、許可されることではありません。 PATH が外を指していれば、コマンドが実行してはいけないプログラムが見つかり、拒否がそれを名指しします。

シェルがないので、シェルの構文もありません。 コマンドは一つのリストです（["cargo", "test", "--lib"]）。セミコロン、パイプ、リダイレクト、バッククォート、 $(…) または && は、プログラムにそのままの引数として届きます。二つのコマンドをつなげるには、daimon がそのツールを二回実行します。そのほうがどのみち良いのです。最初の結果を読んでから二つ目を選べるからです。

コマンドにできること、できないこと

ファイル

  • 付与されたフォルダーの中を読み書きする。 そのフォルダーから、Daimond 自身の .daimond ディレクトリを除いたものが、書き込める世界です。
  • 専用の一時ディレクトリ。 書き込み可能で、 TMPDIR がそこを指します。実行が終われば削除され、ほかのどの実行からも届かず、あなたのフォルダーの外でコマンドが書き込める唯一の場所です。 /tmp は隔離領域の外にあります。一時ファイルを書けないビルドは、誰にも読めない理由で途中で失敗します。
  • システム、読み取り専用。 /usr, /etc, /opt そして上の一覧の残りです。
  • それ以外はすべて、カーネルに拒まれます。誰かが書いた検査によってではありません。付与から一つ外のフォルダーにあるファイルは、 Permission deniedが返り、daimon にはファイルの代わりにその拒否が見せられます。

壊れた道具に見える前に、知っておく価値のある帰結が一つあります。付与されたフォルダー全体が書き込み可能であっても、そのフォルダー 自体 は一覧にできず、その中に直接ファイルを作ることもできません。Landlock はディレクトリを付与しつつその一部を留保することができないので、子は一つずつ付与されるからです。一段下のものはすべて、ふつうに働きます。

名前付きのローカルソケットは、常に拒まれる

コマンドは、ほかに何が許されていようと、unix ソケットを作れません。それが犠牲にするのは、ソケットファイル越しのローカルデータベース、 docker、X11 を望むもの、そして ssh-agent. socketpairは、ビルドが自分の子プロセスと話すのに使うペアのソケットで、手を付けられません。ですから cargo build は影響を受けません。

Landlock ABI 9（Linux 7.1）より前では、隔離領域はソケットファイルへの接続をまったく統制しません。実際に測定しました。柵が効いていてネットワークが拒まれている状態でも、デスクトップのセッションバスへの一通のメッセージが、一度も柵に囲まれたことのないプロセスを起動し、柵が拒むファイルを読みます。これは隔離領域からの抜け道であり、その縁のわずかな漏れではないので、無条件で閉じられています。

ssh は動きません

二つの独立した理由がそれを止めていて、どちらか一方を閉じるだけでは足りません。 ~/.ssh は隔離領域の中にありません。どのパスも、あなたが付与したフォルダーから組み立てられるからです。そしてエージェントのソケットは unix ソケットで、上で拒まれています。 git push は SSH越しに、両方の理由で同時に失敗します。ホームディレクトリを付与すれば、最初の理由も、隔離領域の意味の大半も失われます。だからこそインストーラーはそれを拒みます。

リポジトリだけに触れる操作はうまくいきます。 git status, diff, log, add 、そしてローカルの commit は、あなたが付与したフォルダーの中の、ふつうのファイル操作です。

ツールチェーンには付与が要る

diamond を開くと、作業領域パネルに ツールチェーン の行が現れ、五つのボタンがあります。 Rust, Node, Python, Go, Git。五つとも既定でオフになっているので、 cargo は Rust をオンにするまで拒まれます。 ~/.cargo と ~/.rustup は、あなたのホームディレクトリの下にあり、ホームディレクトリは隔離領域の中にないからです。

Git は例外です。 git はすでに読み取り専用の基盤の中にあり、だからこそ git status と、ローカルのコミットが、付与なしで動きます。ボタンが加えるのは、あなた自身の設定——名前、メール、そして core.hooksPath が名指しするフック——を、読み取り専用で加えます。保存されたパスワードと ~/.ssh は、名前で拒まれます。

それについて、三つのことは意図的です。

  • 実行を頼まれたものから推測されることは、決してありません。 要求されたバイナリに合わせて自分を広げる隔離領域は、モデルが選ぶ隔離領域になってしまいます。この仕組み全体は、隔離領域がモデルの選べないものであることに懸かっています。 cargo が届くのは、あなたが Rust のツールチェーンを付与したからで、ほかの理由はありません。
  • diamond ごとです。 付与は一つの diamond に属し、その diamond が持つフォルダーと並びます。取り消し方も同じです。
  • 名指しされたディレクトリの短い一覧であって、ホームディレクトリでは決してありません。 Rust が付与するのは、 ~/.cargo/bin と ~/.rustup を読み取り専用でです。レジストリとキャッシュを書き込み可能にするのは、cargo がそれらに書き込まずにビルドできないからです。そして 拒むのが ~/.cargo/credentials.tomlです。あなたの crates.io のトークンが書かれている場所です。ほかの四つも同じように引かれていて、それぞれ秘密を持つファイルを外しています。

ネットワーク

コマンドがネットワークに届けるかどうかは、権限のモードと、そのやり取りがすでに何を読んだかによります。 毎回尋ねる と 見張り付きの下では、やり取りがいったん外からの内容——読んだり取得したりしたウェブページ、メール、前のコマンドの出力——を取り込むと、そのやり取りの中のすべてのコマンドは TCP を拒まれた状態で走り、daimon はその理由を伝えられるので、壊れたプロジェクトの代わりに原因を報告します。 素通り の下では、そのやり取りが何を読んでいようと、ネットワークは保たれます。

コマンド自身の出力も、外からの内容に数えられます。 ですから、あるやり取りの最初のコマンドにはネットワークがありますが、同じやり取りの二つ目にはありません。ビルドログは、ビルドが実行した何かによって書かれるので、これは意図的で、人を驚かせます。自分の作業領域にあるふつうのファイルを読むことは数えられませんが、メールの中のメッセージは数えられます。何かを取得する必要があるなら、新しいメッセージで頼んでください。それが新しいやり取りを始めます。

拒まれるのは TCP の bind と connect で、それが Landlock の統制するものです。UDP と raw ソケットはその外にあります。

32 ビットのバイナリは強制終了される

システムコールのフィルターは一つのアーキテクチャ向けにコンパイルされていて、まずアーキテクチャを確認します。互換性のための ABI は呼び出しを違う番号で振るので、間違った表のために組まれたフィルターは、間違ったものを拒み、成功を報告してしまうからです。ですから、違うアーキテクチャを宣言するプログラムは、フィルターにかけられる代わりに、はなから強制終了されます。これは安全側に倒れる失敗で、32 ビットのヘルパーを exec するビルドは、ここでは動きません。

権限のはしご

一つの設定に三つの段があり、その軸になっているのは、Daimond が 尋ねずに何をするかです。始まりは見張り付きです。

毎回尋ねる

どのコマンドも、走る前にコマンドとディレクトリをプロンプトに添えてあなたに諮られます。Daimond は、ウェブに届く前に会話ごとに一度尋ねます。一歩ずつ見守りたいときや、失うわけにいかないものを抱えた機器で選んでください。

見張り付き

既定です。コマンドは尋ねずに走ります。外からの内容を読んだやり取りはネットワークを失い、Daimond はその会話の中で、モデルが選んだどこかに届く前に一度尋ねます。一度のはいが、その会話が終わるまですべてのサイトを覆います。新しいチャットや新しい daimon はまた尋ね、異例に長いアドレスは常に単独であなたに諮られます。

素通り

何も尋ねられません。ただし、見張りのないエージェントがページで行いたいクリックだけは別で、それは常にあなたに諮られます。コマンドは走り、ページは取得され、ネットワークを必要とするビルドは、そのやり取りの十番目のコマンドでも最初のコマンドと同じくネットワークを持ちます。一度、意図して選べば、あとは静かです。

段が、可能なことを変えることはありません。 コマンドが走る隔離領域、その下のシステムコールのフィルター、diamond が限られるフォルダー、付与されたツールチェーン、外からの内容への印付け、そしてジャーナルは、三つの段のどれでも同じです。段が変えるのは、あなたに尋ねられることだけです。

段は、モデルの横にあるチャットのヘッダーの中の一語です。覚えておかなければならないモードは、間違えるモードだからです。クリックすれば変えられますし、あるいは Ctrl K (Cmd K （Mac の場合）を押して、段の名前を入力します。

型破りなシステム

隔離領域は、絶対パスの固定された一覧から組み立てられていて、その一覧が、ある機器で動くかどうかを決めます。 --report を、どちらとも決めてかかる前に、あなたの機器で実行してください。

動かないもの

  • NixOS と Guix。 プログラムがあるのは /nix/store または /gnu/storeで、どちらも付与されていません。そして /usr/bin にはほとんど何もありません。そのままの名前は PATH を通じて、隔離領域の外にあるストアのパスへ解決され、コマンドは名前で拒まれます。このアプリは、今日のところそれを広げられません。
  • Landlock のないカーネル。 それは、Linux 5.13 より前であるか、コンパイルから外されているか、有効な LSM の一覧にないか、あるいは堅牢化パッチで取り除かれている、という意味です。hand は fence:none と報告し、Daimond は柵のないコマンドを実行する代わりに、すべてのコマンドを拒みます。確認すべきは、 landlock が含まれているかどうか、その場所は /sys/kernel/security/lsm.
  • x86-64 でも aarch64 でもないアーキテクチャ。 フィルターのシステムコール番号はアーキテクチャごとに書き出されていて、三つ目の表はありません。hand はそれを推測しないので、フィルターは存在せず、フィルターがなければコマンドは一つも走りません。

部分的に

  • Linux 5.13 から 6.6。 ファイルは柵で囲まれますが、Landlock は Linux 6.7 より前にはネットワークの規則を持たないので、ネットワークを取り上げられて走るはずだったコマンドは、失うはずだったネットワークを持ったまま走る代わりに、そう伝える一文とともにはなから拒まれます。素通りは働き、見張り付きはやり取りが何かを読むまで働きます。
  • Linux 上の Homebrew、Flatpak、Snap。 どれも /home/linuxbrew/.linuxbrew、Flatpak のツリー、あるいは /snap も付与されていません。ですからそうした方法でインストールされたプログラムは拒まれますが、あなたのディストリビューションが /usr の下に置いたものは、同じセッションの中で届きます。これは、コマンドが実行するプログラムについての話です。そうした形で梱包されたブラウザは別の問題で、しかも致命的な問題であり、 始める前に.
  • 知られている二つ以外のバージョンマネージャー。 ツールチェーンのパスは固定された一覧で、 ~/.nvm と ~/.pyenv が、そこにある唯一のバージョンマネージャーです。 asdf, mise, volta, rbenv と sdkman がインストールされる先は ~/.asdf, ~/.local/share, ~/.volta, ~/.rbenv と ~/.sdkman。それらのどれにも付与はありません。Python の付与が対象にするのは ~/.local/bin と ~/.local/lib であり、意図的に ~/.local/share.

問題なし

  • Debian、Ubuntu、Fedora、Arch、openSUSE を、それぞれのパッケージで使う場合。カーネルが十分新しく、 --report が Landlock の ABI を名指しできることが条件です。
  • musl と Alpineも、同じ条件のもとで。
  • BusyBox の coreutils。 マルチコールバイナリは、呼び出された名前から自分が何であるかを決めます。hand は、解決したバイナリを 頼まれた名前のもとで実行するので、自分がどのツールであるべきかを、それでも知っています。

ターミナルも

ターミナル パネルは、同じ機器の、同じ隔離領域の中に、本物のターミナルを開き、そこに打ち込めます。存在する理由は、ターミナルに向かって問いを発し、標準入力には発しないプログラムがあるからです。キー入力はジャーナルに書かれません。ここのほかのすべてと同じく、ペアリングされた hand が要ります。

記録されるもの

すべての実行——何が頼まれ、何が拒まれ、何を返したか——は、 ~/.local/share/daimond/hand/journal/のジャーナルに、あなたが読めるふつうの JSON 行として追記されます。エントリはハッシュで連鎖しており、ジャーナルはどの隔離領域の外にもあります。hand が、そこに届くような柵を拒むからです。ですからコマンドは自分自身の記録を書き換えられず、どの権限モードもこれをオフにはしません。

守られないもの

--report は二つの一覧を表示し、二つ目こそがそれを実行する理由です。そこにあるどの項目も、動いているカーネルで実測されたもので、推測ではありません。あなたのカーネルによって変わるので、自分のものを読んでください。項目はいくつかの群に分かれます。

  • ファイルについて尋ねることは、それを開くことではありません。 stat は隔離領域の外でも答え続けます。ですから大きさ、タイムスタンプ、所有者、そしてファイルの有無は読めます。隔離領域が統制するのは、開くことです。
  • システムへの付与は広いものです。 /usr, /etc と /opt を読み取り専用にすることが、そもそもコマンドを走らせられる理由です。それはまた、 /etc の下にある、誰でも読めるファイルはすべて読め、機器のどのツールも実行できる、という意味でもあります。 /etc は特に、機器を特定する詳細を大量に持っています。
  • フィルターは拒否リストです。 名指しされたケーパビリティをコマンドから取り除くものであって、システムコールのサンドボックスではありません。名指ししなかったものはすべて許可されます。将来のカーネルが加える呼び出しも含めてです。
  • フィルターはポインターをたどれません。 見えるのはシステムコール番号と六つのレジスタだけで、それらが指す先は決して見えません。ですからパスも、アドレスも、ファイル名も見えません。拒まれた chmod は、だからこそどこでも拒まれ、許されたものはどこでも許されます。 chmod 777 は拒まれ、 chmod 644 を秘密鍵に対して行うのは拒まれません。644 は書き込みを加えず、cargo が展開するすべてのものに設定するモードだからです。
  • タイムスタンプは、どこでも守られていません。 コマンドは、機器のどの部分にあるファイルの時刻でも書き換えられます。cargo が、そうしなければレジストリから crate を展開できないからです。それは、ビルドを動かし続けることが守りを犠牲にした、いちばんはっきりした場所です。
  • すでに開かれているもの、すでに作られた名前。 隔離領域が効き始める前に開かれたファイルディスクリプタは、そのまま動き続けます。以前に作られたハードリンクは、同じファイルの二つ目の名前です。コマンドは、拒まれたサブツリーへ向けて新しく作ることはできず、すでにあるものを取り消すこともできません。
  • 「あなたのフォルダーの中だけ」の唯一の例外は、 上で述べた専用の一時ディレクトリです。

取り消す

取り消せることが三つ違ってあり、そのどれもが実際に起こります。

  • 許可を取り下げる。 ツールバーの Daimond Hands のアイコンをクリックします。 このコンピューターでコマンドを実行する は、承認したサイトの横に、取り消すボタンとともに並んでいます。取り消すと、その瞬間に動いているものが即座に止まり、いまのビルドの終わりを待ちません。
  • フォルダーを取り上げる。 削除してください、 root.txtを。hand はそのあと、ブラウザが何を言おうと、まったく提供を拒みます。拒否はまるごとの一文です。
  • 登録を取り除く。 実行するか、 hand/install/uninstall.sh、あるいは --dir DIR を付けて一つのディレクトリに対して実行してください。これは、インストーラーが書いたファイルを削除するので、ブラウザはもう hand を起動できなくなります。バイナリはそのままの場所に残ります。スクリプトがそこに置いたものではないからです。
