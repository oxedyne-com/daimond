モデルとプロバイダー

daimon はモデルで考えます。すでにお持ちの鍵を持ち込んでそのプロバイダーに直接支払うか、クレジットを買って Daimond に動かしてもらうか、どちらかです。

自分の鍵

レール下部のモデルの行を開きます。使っているプロバイダーごとの鍵と、新しい仕事がどのモデルで始まるかが並びます。 + プロバイダーを追加 は、プロバイダーが誰であっても同じ三つの問いをします。

  1. プロバイダーを選ぶ

    Anthropic、Fireworks AI、OpenRouter、Together AI、Groq、または DeepInfra。 カスタム を選ぶと、 ベース URL の欄が現れ、同じチャット API を話すほかのサービス——自分のマシン上のものも含めて——を指定できます。

  2. 鍵を貼り付ける

    パスフレーズのもとで包んで保存され、送られるのは選んだプロバイダーだけで、ほかの誰にも送られません。ほかの端末に届くのも、暗号化された同期の荷物の中に、包まれたままの姿でだけです。

  3. 既定のモデルに星を付ける

    モデルを一覧 は、プロバイダーが持っている場合にカタログを取ってきます。なければモデル ID を打ちます。星を付けたものが、新しいチャットと diamond の始まる場所です。

そのあと、あなたのメッセージはあなた自身のアカウントでそのプロバイダーへ直接届きます。Daimond は経路に入らず、こちらは何も請求しません。

別のモデルを選ぶ

既定のモデルは出発点にすぎません。つないであるモデルなら、ヘッダーの選択欄からそのチャットだけに選べます。既定はそのままです。diamond には、専用の ヘルパーモデル を、送り出すエージェント用に別途持たせることもできます。これは次に送り出すものから効き、すでに走っているものには効きません。

モデルがコンテキストウィンドウを公開していない場合、タイルには このモデルのコンテキストサイズは不明です。 と出て、推測はしません。

サービスの提供元を選ぶ

ルーターは、好きな上流のプロバイダーへモデルを渡します。どれも同じ質とは限りません。OpenRouter のプロバイダーでは、モデルの行それぞれに プロバイダー という欄があり、プレースホルダーは prefer, -avoid, !.

  • そのままの名前は、そのプロバイダーを優先します。
  • 先頭の - を付けると、それを避けます。
  • 単独の ! は、これらだけを使うという意味で、代替をすべて拒みます。

たとえば Novita, -DeepInfra は、一方を優先しもう一方を避けます。この欄は、そこを離れると保存されます。カタログをまだ取得していないプロバイダーは、行を モデル… という開閉の裏に置きますが、すでに設定した優先はそのまま届きます。

クレジット

クレジットは、鍵なしであなたの代わりにモデルを動かし、ブラウザの外に出るわずかなもの——ページの取得、メールと端末間同期の帯域、そして無料枠を超えたクラウド保存——も計測します。同期、メール、クラウド保存そのものを開くのは Daimond Pro で、計測される利用はそれがあってもなくてもクレジットから支払われます。

クレジットの行を開くと、残高と買えるパックが見られます。クレジットはサブスクリプションではなく、買った分はそのまま残ります。支払いは決済プロバイダー自身のページで行われるので、カード番号を Daimond に打ち込むことはありません。

テストが非公開のあいだ、クレジット付きの新しいアカウントはパスコードで配られます。自分のプロバイダーの鍵があれば、パスコードなしで Daimond は使えます。

自動チャージ

自動チャージは、クレジットが少なくなったら買っておく、という常時の指示です。長い仕事が途中で止まりません。あなたが席にいないあいだに Daimond が保存したカードへ請求しうる唯一の場所なので、あえてはっきりさせてあります。設定する数字は三つです。

  • 残高がこれを下回ったら 、そこでチャージが働きます。
  • 買う金額 が、一度のチャージで足す量です。
  • 「1 か月にこれ以上は使わない」 というのが、暦の一か月に対する硬い上限です。ここは慎重に設定してください。請求と同じコードの道筋で効きます。

保存したカードがないと、これはオンにできません。オンになったのに黙って失敗する操作は、使えないと理由を言う操作より悪いからです。
