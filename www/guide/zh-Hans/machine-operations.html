你的电脑

Daimond 可以在你的电脑上运行程序——一次构建、一套测试、一个检查工具、一个脚本——在一个由内核强制执行的隔离舱里。这是免费的，只需要在终端里敲两条命令，而且仅限 Linux。在敲任何一条命令之前，先读一下下面的警告。

一个 snap 或 flatpak 版的浏览器做不到这件事，也没法被强行改成能做到。 安装脚本会检测到这种情况，宁可拒绝也不往里面写，所以这是你会遇到的第一件事——而且在 Ubuntu 上，默认的 Chromium 就是一个 snap。 为什么，以及该装什么来代替.

它给你什么

装好 hand 之后，一个 daimon 就可以对你授权的文件夹运行一次构建、一套测试、一个检查工具或一个脚本，并读取结果。这台机器上别的任何东西都够不到。

它用到的工具，点在 工具 面板里，其中四个值得记住名字。

  • run 运行一条命令——以一份参数列表的形式给出——并给出退出码、输出的尾部，以及花了多长时间。
  • verify 运行你项目自己的检查。Daimond 从 .daimond/verify.json读取参数列表，否则从 Cargo.toml, package.json, pyproject.toml 或者 go.mod推断出来。退出码就是结论。
  • runs 列出仍在运行的东西，以及怎么停掉一个。一条命令可以活得比它那一轮更久，因为在后台启动的东西会一直占着自己的端口，直到被停掉；而且这台电脑上别的任何东西都够不到它，因为隔离舱把信号的作用范围限定在自己里面。
  • serve 为一个文件夹启动一个只读的文件服务器，好让构建出来的页面能在 网页 面板里看到。它在这一轮结束后仍然开着，所以要按它的 id 把它停掉。

一次拒绝会点出路径、原因和修法，所以没有代码要查。这一轮之后会像任何一轮一样结束，标为 已回答, 已停止 或者 达到步骤上限，所以一条被拒绝的命令绝不会读起来像是成功了。

开始之前

有三件事决定这一切是否能用。检查它们要花一分钟，事后才发现要花一个小时，因为浏览器报出的错误一个都不会点名。

1. 浏览器装自一份 .deb

一个 snap 或 flatpak 版的浏览器，会把它启动的程序关起来，这层禁闭也会波及 Daimond 的 hand。 home 接口，snap 拿到的这个接口不会授权你主目录顶层那些隐藏目录，而 hand 把它的日志放在 ~/.local/share/daimond/hand/journal/，就在其中一个隐藏目录后面。hand 打不开它本该把原因记进去的那个文件，所以它一声不吭地退出，Chrome 只会报出 Native host has exited这句话。这句话没给你留下任何可以下手的地方，而这种禁闭正是 snap 存在的意义。搬动日志的位置没有用，因为浏览器会把它自己的环境交给这个程序。

你不必自己把这些搞清楚。安装脚本会往能用的配置文件里写，并点出哪些不能用；如果它找到的每一个浏览器都被关着，它就会停下来，不会留给你一个看起来成功、其实没用的安装。 --check ，即使旁边就有一个能用的浏览器，也会标出一个被关起来的浏览器，因为起作用的是你实际在用的那个。

开始之前，看看你手上有什么：

snap list 2>/dev/null | grep -Ei 'chrom|brave|vivaldi|edge'
flatpak list 2>/dev/null | grep -Ei 'chrom|brave|vivaldi|edge'

任何一条命令点出名字的，都是被关着的。能用的是 Chrome、Brave、Vivaldi 或 Edge，装成一个 .deb，或者一个 .deb 版的 Chromium，来自 Ubuntu 官方仓库以外的地方。

apt install chromium-browser ，给你的是那个 snap。 Ubuntu 的 chromium-browser 这个包，从 20.04 起就是个只会装那个 snap 的空壳，所以不用软件商店获取浏览器的常规办法，会把你带到同一个地方。装上面四个 .deb版本里的一个来代替。

2. 安装之前，先把那个浏览器打开一次

安装脚本会往浏览器的配置文件目录里写一个小文件，而这个目录要等浏览器第一次启动时才会被建出来。装了一个浏览器却从没打开过它， install.sh 就会如实报告什么都没找到，因为那时候确实什么都还没有。

3. Linux，内核里有 Landlock

这个隔离舱是用 Landlock（围住文件）和 seccomp（过滤系统调用）搭出来的，两者都是 Linux 内核的特性。Landlock 是从 Linux 5.13 开始有的， 非常规系统 说明了更老、更特殊的机器能拿到什么。hand 在 macOS 和 Windows 上能构建、能运行，但会报告自己什么都围不住，于是 Daimond 会拒绝每一条命令，而不是运行一条没有围栏的。拒绝会点出缺了什么。这两个平台的围栏都还没做出来。

要装一个不同的浏览器？你的账户不会自动跟过去。 你的账户是一把签名密钥，存在你建它时用的那个浏览器里。密码短语不会重新造出那把密钥，只会解开存在那里的那一份，所以同一句密码短语，在一个全新的浏览器里开出的是一个 另外的 账户，有它自己的额度，没有 Pro。这把密钥本身得能搬家，所以在你退役旧浏览器之前，先在里面做以下一件事： 关联另一台设备，然后在新浏览器里输入那个码；添加一个通行密钥；或者 导出一份备份，把聊天、diamond 和工作区文件连同密钥一起写下来，密钥仍然被你的密码短语包着，供一个还没有账户的浏览器采用。参见 不止一台设备 和 安全和修复.
这和 Machine 工作区不是一回事。 本机 标签，在 工作区 面板里，给 Daimond 一个你硬盘上真实文件夹的读写权限。「在本机运行命令」让它能 运行程序。这是两个分开的授权，分开给。「运行命令」确实需要这个工作区，因为一条命令要针对一个真实的文件夹运行，所以这个工作区必须是一个真实文件夹，而且是同一个。

安装它

安装要在 Daimond 仓库的根目录下，在终端里敲两条命令，然后在浏览器里做两件事。加起来，是每个浏览器配置文件里一个小小的 JSON 文件，再加上一个你自己构建的二进制文件。安装完不会留下任何监听端口的东西，没有守护进程在跑，也没有秘密可偷。

  1. 构建 hand

    cargo build --release --manifest-path hand/Cargo.toml

    用 --manifest-path 而不是 -p，因为 hand 是它自己的一个 cargo 工作区，所以 -p 会报告没有这个包，什么都不会构建。

  2. 授权一个文件夹，并注册 hand

    hand/install/install.sh --workspace ~/work

    把你自己的文件夹换到 ~/work的位置。这个文件夹框定了任何命令能读写的全部范围，所以要选一个用来干活的文件夹。这个脚本会直接拒绝你的主目录，也拒绝 / ，因为授权其中任何一个都等于授权一切。这个文件夹必须已经存在。

    运行这一次，会做三件事，每一件不做好，你迟早都会撞上一个失败。

    • 把你的文件夹写进 root.txt，位置在 ~/.local/share/daimond/hand/journal/root.txt。hand 在被告知这个文件夹之前，不会为任何页面服务，而且它从不猜测，因为猜一个文件夹，就是在猜一条命令可以碰什么。以后要改，就用一个不同的文件夹再运行一次同样的命令。
    • 以 700 模式创建那个日志目录。 它保存着每一个 diamond 运行过的每一条命令的记录，所以 hand 拒绝把它写在别的用户能读到的地方。用平常的默认权限建出来的目录是 755，那样的话 hand 不会启动。
    • 写入注册信息 ，写进每一个能用的浏览器配置文件里，并打印出是哪些。正是这个文件，才让浏览器能够启动 hand。它只是 JSON，没有别的，所以这个脚本不构建任何东西，不下载任何东西，不启动任何东西，也不需要 root 权限。
    DAIMOND_HAND_ROOT 是一个陷阱。 这个环境变量做的是和 root.txt 一样的事，并且优先级更高，但它不会起作用，因为你的浏览器启动 hand 时，用的是 它自己的 环境，你的环境变量不在里面。用那个文件。

  3. 加载扩展

    上一步打印出了路径。打开 chrome://extensions，打开 开发者模式，选择 加载已解压的扩展程序，然后选中 ext/ 目录。

    这个扩展带着一把固定的公钥，所以它在每一台机器上的 id 都一样，这也是刚才写入的注册信息已经能点出它名字的原因。它的清单文件只点名了一个来源， https://daimond.oxedyne.com，作为唯一被允许跟它说话的页面，所以你浏览器里别的任何页面都完全够不到它。

  4. 重启浏览器

    浏览器只在启动时读取那些配置文件目录，所以一个在它运行期间才出现的文件，要等到那时候才会被看见。忘了重启，是一次正确的安装看起来像是坏掉的最常见原因。

然后检查一下

hand/install/install.sh --check

这个检查不会改变任何东西，只为每一件必须成立的事打印一行：一个能用的浏览器、注册信息、这个二进制文件、日志目录和它的权限模式， root.txt、日志目录位于被授权文件夹之外，还有这个扩展。失败的一行，修法就写在它下面一行。从上往下逐一处理，因为靠后的一行常常只是因为前面一行没弄好才失败的。

最后两步由你来做

上面这些步骤，没有一步替你做决定。剩下的两件事，才是真正的决定。

在 Daimond 里打开同一个文件夹。 在工作区面板里，用 本机 标签，打开你授权的那个文件夹。必须是同一个。hand 会往 <folder>/.daimond/workspace.id 里写一个令牌，并在自我介绍时点出它的名字；页面则通过自己已经握着的句柄读这个文件，把两者对比。一个是浏览器自己存储的工作区，或者是一个和 root.txt里不一样的文件夹，它的命令都会被拒绝，并附一行说明是哪一种。这个令牌住在 .daimond 因为隔离舱永远拒绝那个目录，所以一条命令读不到这个令牌，也没法替一个它不在其中的文件夹说话。

允许第一条命令。 Daimond 第一次想运行点什么时，一个 Daimond Hands 窗口会打开来问。没有哪个浏览器权限涵盖「可以在这台电脑上运行程序」，所以这扇窗口 就是 那个批准，扩展自己记录你的回答。这也正是它能被撤销的原因，因为浏览器没有什么可以拿走的。在你允许之前，什么都不会运行。

这扇窗口会点出文件夹和提出请求的页面，并用一行字说明一条命令在这台机器上能碰到多远。 这管着什么，又不管什么 ，打开其余的部分：这个隔离舱拦住了什么、没拦住什么，以及怎么收回这个权限。

不管用的时候

先用 install.sh --check 再来一次。它会按顺序走一遍这里的每一项检查，在第一件出错的事上停下。它自动化的那三步，本身也很有用，是在 --check 通过、Daimond 却还说没有 hand 时该去用的东西。

自己运行 hand

hand/target/release/daimond-hand < /dev/null

这会像你的浏览器那样精确地启动 hand，只是另一端没有浏览器，所以它本来要跟浏览器说的话，都会说给你听。有三种回答。

  • daimond-hand: the page closed the pipe. hand 已经配置好，随时可用。不对劲的地方在浏览器那一侧，先试着重启它。
  • This hand has not been told which folder it may work in ，意思是 root.txt 缺失了。再运行一次 install.sh --workspace 。
  • …is readable by users other than its owner ，意思是日志目录不是 700 权限，hand 不会把你命令的记录写在别的账户能读到的地方。 chmod 700 它。

别的任何情况，都会是一整句话，点出路径、原因和修法，因为 hand 没有地方可以打印一个谁都能去查的代码。

hand/target/release/daimond-hand --report

这会打印出隔离舱在 这台 内核上能强制执行什么，以及篇幅更长的、它不能强制执行什么。仔细读第二份列表，因为在低于 Linux 7.1 的内核上，它包含 一条走出隔离舱的路 ，这条路是 Landlock 留开的，hand 自己把它关上的办法是拒绝 unix 套接字。它还会点出来自 root.txt的那个文件夹，所以一个过时的文件夹会在这里现形，而不是等到第一条命令才现形。

读日志

tail -n 5 ~/.local/share/daimond/hand/journal/hand-*.jsonl

这份日志每行一个 JSON 对象，按事情发生的顺序排列：握手、每一条命令，以及每一次拒绝连同它的理由。只要 hand 启动过，这里就会写下点什么。一次失败尝试之后是空目录，就说明 hand 根本没走到那一步，在 Ubuntu 上，这几乎总是意味着这一页最前面说的那个被关起来的浏览器。

问这个扩展

在浏览器里，在 Daimond 标签页上，打开开发者控制台，运行：

await DaimondHand.status()

这个扩展会用 JSON 回答：是否配对了一个 hand、它说自己被授权了哪个文件夹、它能强制执行什么，以及在答案是否的地方，一个 reason 写成一整句话的原因。Daimond 会把同一句话给模型看，所以这份 JSON 解释的，正是这个 daimon 被告知了什么。

它实际上是什么

一条命令就是一个普通的进程，属于你，跑在你自己的内核上，针对你自己的文件，只是先被拿掉了一些能力。没有虚拟机，没有容器，没有模拟，所以什么都不是模拟出来的，什么都不是复制进来的。四个部分各司其职。

  • 页面提出请求。 Daimond 算出这一轮可以碰什么，把整条规则连同请求一起发出去。它从不发一行 shell 命令，因为 argv——参数列表——是一个数组，没有什么地方可以被注入。
  • 扩展转发。 Daimond Hands ，是页面唯一能把一条命令交给的东西，而且只有一个来源能跟它说话。
  • 一个本地小程序来运行它。 hand 根据收到的那条规则搭出隔离舱，把它套在自己身上，然后 变成 这条命令本身。没有一个监督者盯着一个子进程，因为命令一旦开始，hand 就什么都不剩了。
  • 你的浏览器启动 hand。 这就是为什么没有端口，也没有密码。一个开在端口上的服务，会被你访问的每一个页面都够得到。
这是免费的，不是 Pro 的一部分。 一条命令的任何部分都碰不到 Daimond 的网关。请求从页面到扩展、到你自己硬盘上的一个程序，再原路返回，所以没有什么被计量。一条命令的花费，就是模型思考它要花的钱，和任何别的一轮一样。

Daimond 不实现任何工具

没有内置的 ls，也没有内置的 grep，没有捆绑的工具箱，也没有 shell。 ls 就是 /usr/bin/ls，就是你机器上已经有的那个，版本是你装的那个版本。

系统目录下的每一个程序都够得到，因为隔离舱把它们加进了授权里， 只读: /usr, /bin, /sbin, /lib, /lib32, /lib64, /libx32, /etc, /opt，以及那些无害的设备 /dev/null, /dev/zero, /dev/full, /dev/random 和 /dev/urandom。没有它们，什么都启动不了，连 cat都不行，因为加载器得读共享对象，进程也得为标准流打开点什么。

一个光秃秃的名字，会在 PATH上查找，也就是 /usr/local/bin:/usr/bin:/bin ，除非一个被授权的工具链往里面加了东西。查到的结果会被解析成一个绝对路径，像别的任何东西一样接受隔离舱的检查，所以查到不等于被允许。一个指向外部的 PATH ，会找到一个这条命令不可以运行的程序，拒绝会点出它的名字。

没有 shell，所以也没有 shell 语法。 一条命令是一份列表（["cargo", "test", "--lib"]），一个分号、管道、重定向、反引号， $(…) 或者 && 到达程序时都只是一个字面意义上的参数。要串联两条命令，daimon 会把这个工具运行两次，反正这样更好，因为它可以先读第一次的结果，再决定第二次。

一条命令能做什么，不能做什么

文件

  • 在被授权的文件夹里读写。 那个文件夹，减去 Daimond 自己的 .daimond 目录，就是可写的整个世界。
  • 一个私有的临时目录。 它是可写的， TMPDIR 指向它；运行结束就删掉；别的任何一次运行都够不到它；它是你文件夹之外，一条命令唯一可以写的地方。 /tmp 在隔离舱之外，一次连临时文件都写不了的构建，会半途而废，而且没有人能读懂原因。
  • 系统，只读。 /usr, /etc, /opt ，以及上面那份列表里的其余部分。
  • 别的一切都被内核拒绝，而不是被某人写的一个检查拒绝。一个在授权范围之外一层的文件，返回的是 Permission denied，daimon 看到的是这个拒绝，而不是这个文件。

有一个后果值得先知道，免得它看起来像个坏掉的工具。当整个被授权的文件夹都可写时，这个文件夹 本身 却没法被列出来，也没法直接在里面新建一个文件，因为 Landlock 没法只授权一个目录、又扣下它的一部分，所以是一个一个地授权它的子项。往下一层的任何东西都正常工作。

命名的本地套接字，永远被拒绝

不管别的方面被允许什么，一条命令都没法建一个 unix 套接字。这会牺牲掉一个走套接字文件的本地数据库、 docker、任何要用 X11 的东西，以及 ssh-agent. socketpair——一次构建用来和自己的子进程说话的配对套接字——不受影响，所以 cargo build 不受影响。

在 Landlock ABI 9（Linux 7.1）以下，这个隔离舱完全不管连接一个套接字文件这件事。我们实测过：围栏生效、网络被拒绝的情况下，给桌面的会话总线发一条消息，就能启动一个从没被围住的进程，读到一个围栏本该拒绝的文件。这是一条走出隔离舱的路，不是边缘上的一丝渗漏，所以它被无条件关闭。

ssh 不管用

有两个各自独立的原因拦着它，只堵上其中一个都不够。 ~/.ssh 不在这个隔离舱里，因为每一条路径都是从你授权的那个文件夹搭出来的。而代理套接字是一个 unix 套接字，已经在上面被拒绝了。 git push 走 SSH 会同时因为这两个原因失败。授权你的主目录能消掉第一个原因，但也消掉了这个隔离舱大半的意义，这就是安装脚本拒绝它的原因。

只碰这个仓库本身的操作是能用的。 git status, diff, log, add ，以及一次本地的 commit ，都是你授权的文件夹里普普通通的文件操作。

一个工具链需要一次授权

打开一个 diamond，工作区面板会显示一个 工具链 行，带五个按钮： Rust, Node, Python, Go, Git。这五个默认都是关的，所以 cargo 会被拒绝，直到你打开 Rust，因为 ~/.cargo 和 ~/.rustup 都在你的主目录下面，而你的主目录不在这个隔离舱里。

Git 是个例外。 git 已经在那份只读的基础清单里，这就是为什么 git status 和一次本地提交不用任何授权就能用。这个按钮加的是你自己的配置，只读——也就是你的名字、你的邮箱，以及 core.hooksPath 点名的那些钩子。你存的密码，还有 ~/.ssh ，都被点名拒绝。

这里有三件事是刻意为之的。

  • 它绝不会从被要求运行的东西反推出来。 一个会为了迁就被请求的二进制文件而自己变宽的隔离舱，就成了一个由模型选择的隔离舱，而这整套安排，靠的正是这个隔离舱是模型没法选择的东西。 cargo 够得到，是因为你授权了 Rust 工具链，没有别的原因。
  • 它是按 diamond 来的。 一次授权属于一个 diamond，和那个 diamond 持有的文件夹一样，也用同样的方式收回。
  • 它是一份点了名的目录短清单，从来不是主目录。 Rust 授权 ~/.cargo/bin 和 ~/.rustup 只读，把注册表和缓存改成可写，因为 cargo 不写这些就没法构建，而且它会 拒绝访问 ~/.cargo/credentials.toml——你的 crates.io 令牌写在这里。另外四个工具链都是照同样的方式画出来的，各自都漏掉了那个装着秘密的文件。

网络

一条命令能不能碰到网络，取决于权限模式，也取决于这一轮已经读过什么。在 每次都问 和 有防护档下，只要一轮吸收过外部内容——它读过或抓取过的一个网页、一封邮件、更早一条命令的输出——那一轮里的每一条命令都会在 TCP 被拒绝的情况下运行，daimon 会被告知原因，所以它报出的是原因，而不是一个坏掉的项目。在 跳过 档下，不管这一轮读过什么，网络都保留着。

一条命令自己的输出，算作来自外部的内容。 所以一轮里的第一条命令有网络，同一轮里的第二条就没有。一份构建日志，是构建跑起来的那个东西写的，所以这是刻意的，也常常让人意外。读你自己工作区里一个普通文件不算，你邮件里的一条消息算。如果有什么需要抓取，就在一条新消息里去要，这样会开始新的一轮。

被拒绝的是 TCP 的绑定和连接，这正是 Landlock 管的范围。UDP 和原始套接字不在它管辖之内。

32 位二进制文件会被直接杀掉

系统调用过滤器是为一种架构编译的，会先检查架构，因为兼容 ABI 给调用编号的方式不一样，一个用错表建出来的过滤器，会拒绝错的东西，还报告成功。所以一个声明了不同架构的程序，会被直接杀掉，而不是被过滤。这是往安全的方向失败，一次要 exec 一个 32 位帮手的构建，在这里不会管用。

权限的阶梯

一项设置，三个档级，衡量的轴是 Daimond 不问就做的是什么。它默认在「有防护」档。

每次都问

每一条命令在运行之前都会先给你看，提示里带着命令本身和所在目录；每场对话里，Daimond 碰网络之前也会问一次。想盯着每一步，或者这台机器上有你输不起的东西，就选这一档。

有防护

默认档。命令不问就运行。一轮如果读过外部内容，就会失去网络，Daimond 在那场对话里，去模型选的任何地方之前，会问一次。答一次是，就管到这场对话结束为止；一场新聊天，或者一个全新的 daimon，会重新问。一个异常长的地址，永远会单独拿来给你过目。

跳过

什么都不问，除了一个没人看着的智能体想在页面上点一下——这个永远会先给你过目。命令直接运行，页面直接抓取，一次需要网络的构建，在这一轮的第十条命令上和第一条命令上，网络一样都在。刻意选一次，之后就安静下来。

任何一档都不会改变可能做到什么。 一条命令运行所在的隔离舱、它下面的系统调用过滤器、一个 diamond 被限定的文件夹范围、一个被授权的工具链、给外部内容打的标记，以及日志，这三档全都一样。一档改变的，只是你会被问到什么。

这一档是聊天标题栏里、模型旁边的一个词，因为一个你得自己记住的模式，就是一个你迟早会弄错的模式。点它可以改，或者按 Ctrl K (Cmd K （Mac 上是 Cmd K），然后打这一档的名字。

非常规系统

这个隔离舱是用一份固定的绝对路径清单搭出来的，这份清单决定了一台给定的机器能不能用。先在你的机器上运行 --report ，再假设是哪种情况，不管是哪个方向。

不会管用

  • NixOS 和 Guix。 程序住在 /nix/store 或者 /gnu/store，两者都没被授权，而 /usr/bin 里几乎什么都没有。一个光秃秃的名字，经 PATH 解析出来的，是一个在隔离舱之外的 store 路径，命令会被点名拒绝。这个应用目前没法把它拓宽。
  • 一个没有 Landlock 的内核。 意思是低于 Linux 5.13，或者编译时被去掉了，或者不在生效的 LSM 列表里，或者被一个加固补丁移除了。hand 会报告 fence:none ，Daimond 会拒绝每一条命令，而不是运行一条没有围栏的。检查一下 landlock 有没有出现在 /sys/kernel/security/lsm.
  • 一种既不是 x86-64 也不是 aarch64 的架构。 过滤器的系统调用编号是按架构分别写出来的，没有第三份表。hand 不会去猜一份，所以没有过滤器；没有过滤器，就没有命令能运行。

部分管用

  • Linux 5.13 到 6.6。 文件被围住了，但 Landlock 在 Linux 6.7 之前没有网络规则，所以一条本该在网络被扣住的情况下运行的命令，会被直接拒绝，并附一句话说明，而不是带着它本该失去的网络运行。「跳过」档能用，「有防护」档在这一轮读到什么之前也能用。
  • Linux 上的 Homebrew、Flatpak 和 Snap。 无论是 /home/linuxbrew/.linuxbrew、Flatpak 的目录树，还是 /snap ，没有一个被授权，所以那样装的程序会被拒绝，而你的发行版放在 /usr 下面的东西，在同一个会话里够得到。这说的是一条命令运行的程序。一个用那种方式打包的浏览器是另一个问题，而且是致命的，讲在 开始之前.
  • 已知的那两个之外的版本管理器。 工具链路径是一份固定的清单，而 ~/.nvm 和 ~/.pyenv 是清单上仅有的两个版本管理器。 asdf, mise, volta, rbenv 和 sdkman ，装在 ~/.asdf, ~/.local/share, ~/.volta, ~/.rbenv 和 ~/.sdkman下面，而这些一个都没被授权。Python 的授权涵盖 ~/.local/bin 和 ~/.local/lib ，并且刻意漏掉了 ~/.local/share.

没问题

  • Debian、Ubuntu、Fedora、Arch、openSUSE， 用它们自己的包，内核新到足以让 --report 点出一个 Landlock ABI 版本。
  • musl 和 Alpine，条件一样的话。
  • BusyBox 的 coreutils。 一个多用途二进制文件，靠自己被调用时用的名字来决定自己是什么，而 hand 会 以被请求的那个名字，去 exec 解析出来的那个二进制文件，所以它仍然知道自己该扮演哪个工具。

还有一个终端

终端 面板会在同一台机器上、在同一个隔离舱里，打开一个真正的终端，你直接往里面打字。它存在是因为有些程序会向一个终端提问，而不是向标准输入。按键不会被写进日志。它需要配对一个 hand，和这里的其他一切一样。

记录了什么

每一次运行——被要求做什么、被拒绝了什么、返回了什么——都会追加进 ~/.local/share/daimond/hand/journal/里的日志，是你能读的普通 JSON 行。这些条目用哈希链在一起，而且日志坐落在每一个隔离舱之外，因为 hand 拒绝一道能碰到它的围栏。所以一条命令没法改写自己的记录，也没有哪个权限模式能把这个关掉。

什么没有被保护

--report 会打印两份列表，第二份才是运行它的理由。里面的每一条，都是在一个正在运行的内核上实测出来的，不是推断的，而且会随你的内核变化，所以要读你自己那份。这些条目大致分成几组。

  • 打听一个文件，不等于打开它。 stat 仍然会在隔离舱之外回答，所以大小、时间戳、所有者，以及一个文件在不在，都是可读的。隔离舱管的是打开这件事。
  • 系统这份授权很宽。 /usr, /etc 和 /opt 只读，是让一条命令能运行起来的前提，但这也意味着 /etc 下面每一个所有人可读的文件都能被读到，这台机器上的每一个工具都能被执行。 /etc 尤其装着大量能识别出这台机器的细节。
  • 这个过滤器是一份拒绝名单。 它从一条命令身上拿掉点了名的能力，不是一个系统调用沙盒。任何它没点名的东西都是允许的，包括一个未来内核才会加进去的调用。
  • 一个过滤器没法跟踪一个指针。 它看到的是一个系统调用编号和六个寄存器，从不是它们指向的东西，所以它看不到路径、地址或文件名。一个被拒绝的 chmod ，因此在任何地方都被拒绝；一个被允许的，在任何地方都被允许。 chmod 777 被拒绝，而 chmod 644 对一把私钥不会被拒绝，因为 644 不加写权限，而且这正是 cargo 解包任何东西时设的模式。
  • 时间戳在任何地方都没有被保护。 一条命令可以改写这台机器上任何部分、任何文件的时间，因为 cargo 不这样做就没法从注册表解包一个 crate。这是「让构建能跑起来」牺牲掉覆盖范围最明显的地方。
  • 已经打开的东西，和已经建好的名字。 一个在隔离舱生效之前就打开的文件描述符，会继续工作；一个更早建好的硬链接，是同一个文件的第二个名字。一条命令没法把一个硬链接建进一个被拒绝的子树，也没法撤销一个已经存在的。
  • 「只能在你的文件夹里」唯一的例外， 就是上面说的那个私有临时目录。

收回它

有三样不同的东西可以被收回，三样都会用到。

  • 撤回权限。 点工具栏里的 Daimond Hands 图标。 在这台电脑上运行命令 ，会和你批准过的网站并排列在那里，带一个撤销按钮。撤销会立刻停下当时正在运行的任何东西，不会等当前的构建跑完。
  • 把文件夹拿走。 删掉 root.txt。之后不管浏览器说什么，hand 都会完全拒绝服务，而且拒绝的话是一整句。
  • 移除注册信息。 运行 hand/install/uninstall.sh，或者带上 --dir DIR ，只针对一个目录。这会删掉安装脚本写的那个文件，所以浏览器不能再启动 hand 了。这个二进制文件还留在原地，因为这个脚本本来就不是它放在那里的。
