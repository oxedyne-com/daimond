Files, email & the web

A daimon works from files it can read and write, folders you hand it, mail you can answer, and pages it can show or drive.

The Workspace

The Workspace panel shows your files as an ordinary tree. Three chips at the top name where the workspace lives.

  • Browser is this browser's own private storage, reachable by nothing outside Daimond. It is the default, and it syncs to your other devices.
  • Machine is a real folder on this computer's disk. Daimond works in it directly, so the same files are in your file manager. It stays on that computer, and travels only if you share it with the ⇄ control. Chromium-based browsers only.
  • Cloud is where the bytes are kept, which is what lets a workspace be larger than the device holding it. It is not a third place to work. Files are encrypted before they leave.

The folder you open as Machine is the whole of what Daimond can see, with nothing above it and nothing beside it.

Getting a file in

  • Upload files, the arrow-into-tray in the header, takes one file or a handful.
  • Import a folder… copies a folder in, after which it syncs like everything else.
  • Open a real folder with the Machine chip. Nothing is copied, and it syncs only if you share it.

Mail arrives here as ordinary files, and a daimon writes here where it is allowed to.

Held, in the cloud, or pinned

A file is in one of three states, and the tree says which. Held means it is on this device. In cloud storage means it is only there, marked with a cloud, and clicking it brings it down. Pinned means it is never freed automatically.

As storage fills, the files longest unused go back to the cloud on their own. Freeing is not deleting, since the file is still listed and comes back when asked for.

A daimon is told plainly when a file it wants is in the cloud, and has to fetch it deliberately. A cap limits how much it may bring down on its own.

Handing a folder over

The paperclip on every row reads Attach to current focus. What it does follows what is in focus, whichever row it sits on.

  • A diamond is in focus. The file or folder joins that diamond's workspace and stays until you take it out.
  • A chat is in focus. The attachment is for the next turn only.

Attaching copies nothing. The file stays where it is and the diamond points at it, so attaching one folder to two diamonds still leaves one folder.

Each attachment is either Note, meaning the path is worth knowing and costs a few tokens, or Read, meaning the contents are wanted now. Start with Note, which is much the cheaper. Either way the text it generates goes into the message box in front of what you type, where you can edit or delete it.

Ticking a folder in the workspace group is the permission, so this chat or diamond may then read and change what is inside. Ticking a file only puts it in front of the model. A diamond's Reach row names every folder it may write in, and says so in both trees.

What a daimon can open

A daimon can open only what is in its diamond's workspace. Nothing else is readable or writable through the file tools, by the daimon or by any helper it dispatches. The check is in compiled code at the one door every file tool passes, and that code is in a bundle that builds reproducibly from public source, so it is not an instruction in a prompt.

That rule settles what a daimon can reach and says nothing about where what it reads ends up, because whatever it opens goes to your model provider with the rest of the turn.

The attachment list

Rows carry an age, Added {when}. A path that is no longer there is drawn as Gone with no open action, so a dead row never poses as a live one.

Anything a daimon attached for itself, such as a fold's harvest or a file an agent kept, sits under one collapsed heading, Added by the daimon, with a count and a Drop all. Your own attachments stay where they are.

Sharing a folder to your other devices

A Machine folder lives on one computer, and your phone cannot open it. The ⇄ control on the row is how it reaches one anyway, with Share with devices that lack native access.

Off, only devices that can open the folder themselves see it. On, it is copied to your other devices, up to 200 MiB per folder. The setting is per folder, whichever device you set it from, and only a device that can open the folder can set it.

A folder over the ceiling is left out whole, and a banner says which one and what it weighed. Share a smaller folder, or take some of it out.

Documents, and books

Open a .typ file and the Doc panel gains two buttons. Compile lays the document out in the page and writes a preview PDF beside the source, and while those pages are up, every save rebuilds them. Press it on a chapter and it compiles the document that includes the chapter, then takes you to that chapter's page.

Both panels have to be on screen for the loop to run. Where the window is too narrow, the Doc panel says so, and one rebuild catches up when they return.

The editor need not be Daimond's. A save from any editor writing into the granted folder is picked up within about a second.

A phone cannot hold a book's files or afford the memory a layout costs, so it hands the compile to a paired computer that can, sealed to your account exactly as a turn is, and the laid-out pages come back.

Any kind of file

Any file is stored and travels, up to a gigabyte each. A document or a spreadsheet opens as a reading view, which shows what it says and not how it prints. Values are as stored, formulas are not recalculated, and macros are neither run nor read. Save a copy writes one to your own device and leaves the file here untouched.

Where nothing recognises a file, its bytes are shown, and the panel says so.

Email

A browser cannot open a mail connection, so Daimond connects through the gateway, which hands back the raw message and forgets your credential. Your mail is written into the workspace as ordinary files.

Add a mailbox with the + in the Email panel. Type your address and Daimond guesses the server settings, and every field stays editable. Most providers want an app password in place of your account password, and the panel says where to find it.

The credential is stored on this device under your passphrase, handed to the gateway for one sync, and forgotten. Daimond stores no mail on any server.

Only you can send. A daimon can draft a message into the Compose panel. The Send button is the one thing that puts mail on the wire, and only a person can press it. Email is part of Daimond Pro.

The Web panel

Ask Daimond to open a page, or paste a link. There are three ways, and the site decides which works.

  • Show it. The page appears in the panel. Most sites refuse to be embedded, so this works for a minority.
  • Read it. Daimond fetches the page and reads its text. It works where showing does not. You do not see the page, and Daimond does.
  • Drive it. With the browser add-on, Daimond opens a real tab, signed in as you, and works it while you watch. It is the only way to work a live, logged-in site.

Signing in stays yours. When you sign in on a driven page, Daimond stops watching entirely, taking no text, no picture and no keystrokes, and never sees your password. You hand the wheel back from the browser tab and not from Daimond, so a page cannot take it from you.

Tools

The Tools panel says what Daimond can do. Built-in tools are already yours and free, and the panel lists exactly what is held, so it cannot promise one that is not there. Packs are extras, bought once, in dollars.
